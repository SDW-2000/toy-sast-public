# TOY SAST

TOY SAST는 Java, JavaScript, Python 소스코드를 ZIP 파일로 업로드하여 정적 분석하고, 탐지된 보안 이슈를 프로젝트 단위로 관리하는 웹 기반 SAST 프로토타입입니다.

한국인터넷진흥원(KISA) 「소프트웨어 개발보안 가이드」의 구현단계 보안약점 49개 항목을 기준 카탈로그로 사용하며, Semgrep 기반 탐지 규칙을 실행해 파일 위치와 탐지 근거를 포함한 분석 결과를 제공합니다.

> 이 프로젝트는 포트폴리오 및 기술 검토를 위한 공개 열람용 프로젝트입니다. 실제 운영 환경에 바로 적용할 수 있는 상용 보안 제품이 아닙니다.

## 설치 및 실행

### 최소 실행 환경

- Docker Desktop
- Docker Compose v2
- CPU 2코어 이상
- 메모리 6 GiB 이상, 8 GiB 권장
- 사용 가능한 로컬 포트: `3000`, `8000`, `8025`, `5432`

Docker로 실행만 하는 경우에는 Node.js와 Python을 별도로 설치하지 않아도 됩니다.

### 1. 저장소 준비

```bash
git clone https://github.com/SDW-2000/toy-sast-public.git
cd toy-sast-public
cp .env.example .env
```

### 2. 환경변수 설정

복사한 `.env` 파일에서 다음 값을 설정합니다.

```dotenv
POSTGRES_PASSWORD=충분히_긴_임의의_비밀번호
DATABASE_URL=postgresql://toy_sast:동일한_비밀번호@postgres:5432/toy_sast
SESSION_SECRET=충분히_긴_임의의_세션_비밀값
```

`POSTGRES_PASSWORD`와 `DATABASE_URL`에 입력하는 비밀번호는 동일해야 합니다. 비밀번호에 URL 예약 문자가 포함되면 `DATABASE_URL`에서는 URL 인코딩해야 합니다.

세션 비밀값은 다음 명령으로 생성할 수 있습니다.

```bash
openssl rand -hex 32
```

생성한 비밀번호와 세션 비밀값은 Git에 커밋하지 마십시오.

### 3. 서비스 실행

```bash
docker compose up -d --build
```

실행 상태는 다음 명령으로 확인합니다.

```bash
docker compose ps
```

### 4. 최초 관리자 생성

```bash
docker compose run --rm api \
  python -m app.bootstrap_admin \
  --email admin@example.com
```

명령을 실행하면 사용할 비밀번호를 터미널에서 두 번 입력합니다. 비밀번호는 12자 이상이어야 합니다.

### 5. 접속 주소

- TOY SAST: `http://localhost:3000`
- API 상태: `http://localhost:8000/health`
- API 준비 상태: `http://localhost:8000/ready`
- Mailpit 메일함: `http://localhost:8025`

### 서비스 종료

```bash
docker compose down
```

저장된 사용자, 프로젝트 및 분석 이력을 포함한 Docker 볼륨까지 제거하려면 다음 명령을 사용합니다.

```bash
docker compose down --volumes
```

> `--volumes` 옵션을 사용하면 로컬 데이터베이스에 저장된 데이터가 삭제됩니다.

## 기본 사용 방법

1. 최초 관리자 계정으로 로그인합니다.
2. 프로젝트를 생성합니다.
3. 분석할 소스코드 ZIP 파일을 업로드합니다.
4. ZIP에 포함된 Java, JavaScript, Python 파일이 자동으로 식별됩니다.
5. 분석 실행 버튼을 누릅니다.
6. 분석 진행률과 현재 검사 단계를 확인합니다.
7. 분석이 완료되면 탐지 이슈 목록으로 전환됩니다.
8. 파일 구조, 위험도, 언어 필터를 이용해 결과를 조회합니다.
9. 이슈를 선택하여 탐지 근거와 수정 권고를 확인합니다.

## 탐지 범위

TOY SAST는 KISA 소프트웨어 개발보안 가이드의 49개 보안약점을 결과 분류 기준으로 관리합니다.

현재 룰팩에는 총 86개 규칙이 등록되어 있으며, 신규 분석에서는 취약·정상 예제를 이용해 동작을 검증한 79개 자동 탐지 규칙을 실행합니다.

| 구분 | 현재 범위 |
| --- | --- |
| 기준 카탈로그 | KISA 개발보안 가이드 보안약점 49개 |
| 자동 탐지 대상 기준 | 대표 위험 패턴을 구현한 42개 기준 |
| 실행 규칙 | 79개 |
| 자동 탐지 미지원 기준 | 7개 |
| 지원 언어 | Java, JavaScript, Python |
| 분석 엔진 | Semgrep 1.174.0 |
| 입력 형식 | ZIP |
| 기본 업로드 제한 | 50 MiB |

하나의 보안약점은 언어와 프레임워크에 따라 여러 탐지 규칙이 필요할 수 있습니다. 따라서 49개 보안약점과 실제 실행 규칙의 수는 동일하지 않습니다.

`탐지되지 않음`은 현재 구현된 규칙 범위에서 위험 패턴을 발견하지 못했다는 의미입니다. 해당 코드가 안전하거나 보안 기준을 완전히 충족했다는 의미는 아닙니다.

## 탐지 결과

탐지된 이슈에는 다음 정보가 표시됩니다.

- 이슈 ID
- 개발보안 가이드 기준
- 탐지 규칙 ID
- 분석 언어
- 위험도
- 신뢰도
- 파일 경로
- 시작·종료 위치
- 탐지 메시지
- 탐지 이유와 근거
- 수정 권고
- 참고자료

파일 구조에서 전체 ZIP, 폴더 또는 개별 파일을 선택하여 해당 범위에 포함된 이슈만 확인할 수 있습니다.

### 결과 판정

| 판정 | 의미 |
| --- | --- |
| 탐지됨 | 실행한 규칙이 위험 코드 패턴을 발견함 |
| 탐지되지 않음 | 실행한 규칙 범위에서 위험 패턴을 발견하지 못함 |
| 자동 탐지 미지원 | 해당 기준과 언어에 검증된 자동 탐지 규칙이 없음 |
| 검사 실패 | 분석기 오류 등으로 정상적인 판정을 완료하지 못함 |

## 사용자 초대 테스트

현재 기본 Docker 구성은 실제 외부 이메일 대신 Mailpit을 사용합니다.

1. 관리자 계정으로 로그인합니다.
2. 사용자 관리 화면에서 일반 사용자를 초대합니다.
3. `http://localhost:8025`에 접속합니다.
4. Mailpit에서 수신된 초대 메일을 엽니다.
5. 메일에 포함된 비밀번호 설정 링크로 접속합니다.
6. 초대받은 사용자의 비밀번호를 설정합니다.
7. 관리자 계정으로 해당 사용자에게 프로젝트를 할당합니다.

현재 기본 구성은 로컬 시연을 위한 Mailpit 환경입니다. 실제 이메일을 전송하려면 TLS와 SMTP 인증을 지원하는 외부 SMTP 연동 작업이 추가로 필요합니다.

## 분석 데이터 처리

업로드된 ZIP 파일은 분석 작업을 처리하는 동안 데이터베이스와 분석 작업공간에 임시로 저장됩니다.

분석 완료 또는 실패 처리 후에는 완료된 분석 결과에 원본 ZIP과 소스 본문을 보존하지 않습니다. 대신 다음 메타데이터를 저장합니다.

- 프로젝트와 분석 실행 정보
- 분석 엔진과 룰팩 버전
- 탐지 규칙과 기준 식별자
- 파일 경로와 위치
- 위험도와 신뢰도
- 탐지 메시지와 탐지 근거
- 수정 권고

현재 구현은 암호화 저장, 안전한 삭제 또는 법적 보존 정책을 보장하지 않습니다. 실제 민감한 소스코드를 사용하는 운영 환경에는 별도의 보안 설계가 필요합니다.
